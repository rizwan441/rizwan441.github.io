Selected work

Three problems, how I approached them, and what changed.

01 · Distributed systems

Carrier DID Lookup Platform

Dial Edge Telecom · Architecture & operations
1.18B recordsserved in memory at sub-millisecond latency
Context
Telecom carriers need an instant answer for every phone number (DID) on every call. The dataset held 1.18 billion records, and lookups had to stay under a millisecond.
Approach
Modeled RAM per record and found a 128 GB operational ceiling, then designed a tiered scaling path before it was needed. Built a snapshot-based serving layer that keeps PostgreSQL as the source of truth and serves reads from memory.
Outcome
Sub-millisecond lookups at full scale. Caught an OOM risk mid-build through CPU/RSS monitoring, and resolved a production deadlock (SQLSTATE 40P01) with deterministic ordering and retry.

Simplified architecture. Reads never touch the database; snapshots are rebuilt from PostgreSQL and swapped in.

02 · Observability

Fleet monitoring that sees crashed containers

Dial Edge Telecom · Design & build
4 servers, one viewstaging, production, monitoring and legacy
Context
Infrastructure spanned bare metal and cloud with no single view of health across hosts, containers, databases and endpoints.
Problem
cAdvisor drops a container's metrics the moment it stops, so crashed containers disappeared from dashboards instead of turning red.
Approach
Centralized Prometheus, Grafana and Alertmanager. Wrote a last_over_time + container_last_seen PromQL pattern that surfaces dead containers reliably. Generated 20+ dashboards from Python so they stay consistent, and shipped everything through GitOps with post-deploy health gates.
Outcome
One place to see the whole fleet, alerts that fire on crashes, UFW network segmentation, and a one-command script to onboard new hosts.

03 · Incident response

Network flapping in production

Dial Edge Telecom · Diagnosis & remediation
Root-causedthen redesigned so this failure mode cannot repeat
Symptom
Production nodes intermittently lost network connectivity with no obvious pattern.
Root cause
A UFW firewall sync agent had entered an infinite loop, continuously re-applying rules and dropping connections each time.
Fix
Stabilized production first, then rebuilt the agent around diff-based, idempotent reconciliation, so it only changes what actually differs. Separately moved latency-sensitive telecom services to Docker Macvlan for direct LAN IPs, removing a bridge-NAT bottleneck.
